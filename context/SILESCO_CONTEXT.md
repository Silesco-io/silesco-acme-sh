# Silesco.io: контекст всей системы

## Замысел

Silesco.io — персональная защищённая панель управления Linux-серверами, прежде всего арендуемыми VPS. Она предназначена для обычного пользователя, который хочет развернуть VPN, почту, персональный ИИ-интерфейс, облако или другой self-hosted сервис, но не обязан понимать Docker, порты и reverse proxy.

Главный пользовательский образ продукта: человек нажимает «+», выбирает приложение и получает работающий сервис. Система сама решает вопросы размещения, домена, портов, конфигурации, наблюдаемости и безопасного выполнения необходимых изменений.

Проект возник как ответ на ограничения CasaOS: недостаточную изоляцию, неструктурированный магазин приложений и отсутствие понятного разрешения конфликтов портов. Конкуренты существуют, но цель Silesco.io — не копировать enterprise-панели, а совместить простой личный self-hosting, управление несколькими VPS из одного окна и строгую безопасность без разрушения UX.

## Ценности продукта

1. Простота для пользователя без опыта администрирования.
2. Управление несколькими серверами из единого интерфейса.
3. Минимум публичных точек входа и закрытые внутренние сервисы.
4. Zero Trust между Master и удалёнными нодами.
5. Приватность данных и возможность использовать локальные ресурсы пользователя.
6. Объяснимые действия, безопасные подтверждения и пригодное Disaster Recovery.

Маскот и голос интерфейса — кибер-сова: спокойный и бдительный хранитель серверов.

## Топология

### Master-нода

Единая точка управления. На ней размещаются:

- `silesco-nginx` — единственный публичный HTTP(S)-вход;
- `silesco-ui` — UI и управляющий API на PHP 8.3 / Yii3;
- `silesco-pwa` — пользовательские подтверждения, WebAuthn и TOTP-сценарии;
- PostgreSQL 16 + TimescaleDB — конфигурация, аудит и временные ряды;
- PostgreSQL Command Outbox и Agent API — доставка команд первой версии;
- HashiCorp Vault — секреты, PKI и динамические credentials;
- непрерывное наблюдение Docker выполняет Rust `silesco-agent-observer` под отдельным пользователем группы `docker`; Portainer исключён;
- `silesco-agent-notifier` — Master-служба уведомлений и человекочитаемых сводок;
- локальные профили Core/Guard/Observer/Collector/Backup с теми же privilege boundaries, но без искусственного WireGuard loop;
- мониторинг и вспомогательные службы.

### Agent-нода

Управляемый VPS, на котором пользовательские приложения запускаются в Docker. Вместо отдельной веб-панели работает семейство малых системных служб на Rust/Go:

- `silesco-agent-core` — read-mostly наблюдение, heartbeat, метрики и отчёты;
- `silesco-agent-guard` — привилегированные мутации после проверки политики;
- `silesco-agent-collector` — события CrowdSec и GeoIP;
- `silesco-agent-backup` — резервные копии;

### Source-пир

Неуправляемое устройство пользователя, например домашний ПК с Ollama или LM Studio. На нём не устанавливаются агенты Silesco; стандартный WireGuard-клиент даёт ограниченный доступ к явно разрешённому локальному сервису.

## Базовые потоки

### Развёртывание приложения

1. Пользователь выбирает приложение и домен в UI.
2. UI получает и проверяет подписанный манифест приложения.
3. PostgreSQL сохраняет желаемую конфигурацию.
4. Команда доставляется нужной Agent-ноде с уникальным идентификатором и версией протокола.
5. Если нужны мутации, Guard получает конкретную разрешённую операцию и требуемое подтверждение.
6. Guard создаёт производные файлы, управляет Docker/UFW и возвращает результат.
7. Core наблюдает фактическое состояние; UI сверяет его с желаемым и показывает итог пользователю.

### Безопасная связь

Master принимает WireGuard-соединения. Agent-ноды и Source-пиры всегда инициируют их наружу. Поверх WireGuard межсервисные вызовы Master ↔ Agent используют mTLS с сертификатами от Vault PKI и поддержкой отзыва/карантина.

### Секреты и запуск Master

Локальный Vault поддерживает внешний Cloud KMS, включая опциональный KMS.Silesco.io на отдельном OpenBao Transit, интерактивный PWA/WebAuthn-путь и аварийное восстановление через сохранённые пользователем Shamir-доли. HashiCorp Vault не используется внутри коммерческого KMS.Silesco.io. Unseal-материал никогда не передаётся Agent-нодам.

## Общесистемные качества

- Все логи структурированы и содержат `timestamp`, `level`, `component`, `correlation_id`, `node_id` и безопасное сообщение.
- PostgreSQL хранит желаемое состояние, команды и transactional outbox.
- Потеря Master, PostgreSQL или сети не должна превращать агент в неуправляемый привилегированный процесс.
- Core доставляет metrics/anomaly events по исходящему Agent API; observer не открывает сетевой listener и Core не имеет Docker socket.
- Команды имеют idempotency key и безопасно переживают повторную доставку.
- Локальный буфер телеметрии рассчитан до 24 часов и не содержит секретов.
- Внешние вызовы имеют timeout, ограниченные повторы, jitter, circuit breaker и понятный fallback.
- Миграции БД используют expand-contract и не ломают совместимость при последовательном обновлении компонентов.
- Протокол Master ↔ Agent версионируется; несовместимый агент не получает команды мутации.
- Core (Go), Guard (Rust), Observer (Rust), Collector (Go), Backup scheduler (Go), UI/PWA/installer, hosted KMS и каждый root helper имеют независимую SemVer-версию. Notifier и baseline builder являются Yii3 worker-модулями UI. Готовые Nginx, acme.sh, TimescaleDB/PostgreSQL и Vault не переписываются Silesco; CrowdSec и restic устанавливаются как обязательные host-компоненты Master/Agent, а не production-контейнеры.
- Первоначальный Wizard использует одноразовый self-signed HTTPS URL; первый браузер атомарно привязывает единственную cookie+IP сессию максимум на два часа.

## Что не является целью

- Полноценная enterprise-оркестрация уровня Kubernetes.
- Публичный доступ к административным UI каждого внутреннего инструмента.
- Перенос сложности на пользователя под видом «гибкости».
- Безопасность как набор лишних подтверждений для низкорисковых read-only действий.
- Автоматическое выполнение произвольных shell-команд от Master.

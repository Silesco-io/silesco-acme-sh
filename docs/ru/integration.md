# Подключение PHP-библиотеки — 0.2.0-alpha.1

PHP 8.3+, без Yii3, PostgreSQL, Vault и Silesco Protocol. Composer-пакет
`silesco-io/acme-sh`, namespace `Silesco\AcmeSh\`. Установка через path/VCS;
публикация в Packagist пока не выполнялась. Offline-экспорт:
`node scripts/export.mjs ПУСТОЙ_КАТАЛОГ`; VERSION, UPSTREAM.json и SHA256SUMS входят в пакет.

Начните с [быстрого старта с Composer](../../README.md#quick-start--быстрый-старт):
там есть команды подключения текущей тестовой ветки и запускаемый PHP-пример
чтения каталога без секретов и сетевых запросов. Пример выпуска в английском
руководстве — схема интеграции, а не готовое приложение: значения формы,
защищённое хранилище секретов, UUID операции и настроенный Executor предоставляет
ваше приложение. Публикация стабильного пакета в Packagist — отдельный будущий этап.

Каталог содержит все **198 DNS-драйверов acme.sh3.1.6**, 463 поля и 218 вариантов.
Можно выбрать провайдера, вариант авторизации и получить ru/en подписи, подсказки,
ссылки настройки и дополнительные требования. Для 50 исключений metadata исправлены
после чтения кода драйвера. Сам acme.sh поставляется отдельно и выполняет DNS API/ACME.

`Catalog::bundled()->form('dns_regru','ru')` возвращает форму. HTML обязан экранировать
текст; никогда не исполняйте metadata. `validateCredentials` проверяет точные имена,
обязательность, длину, управляющие символы и несовместимые варианты. Значения по умолчанию
не подставляются автоматически. Условия вроде включённой 2FA или IAM role проверяет
приложение/исполнитель — библиотека не может угадать их и не проверяет доступ к аккаунту.

В CertificateRequest передаётся только непрозрачная ссылка на защищённые credentials.
Для REG.RU нужны логин, альтернативный API-пароль и разрешённый исходящий IP сервера:
ссылка на настройки есть в форме. TXT создаёт и удаляет acme.sh, не PHP-библиотека.

Результат получается через интерфейс Executor. Для стороннего Linux-приложения есть
[необязательный локальный исполнитель](local-executor.md), который требует явной политики.
В Silesco веб-процесс **не запускает его**: используется адаптер существующего пути
bootstrap/Guard/helper. Нельзя передавать браузеру выбор shell-команд, CA или путей.

Повтор неизменного задания возвращает ту же операцию; изменённое содержимое с тем же
UUID отклоняется. Опрос не запускает выдачу повторно. Ошибки — стабильные коды, не ответы
провайдера. `issued` не означает активацию Nginx или готовность PWA; это проверяется отдельно.
Автоматическое продление ещё не реализовано. acme.sh может сохранять credentials в своём
account.conf и печатать их: исполнитель обязан защищать каталоги и все каналы вывода.

Каталог schema2 заменяет schema1 до версии1.0; основные модели запросов/результатов и
Executor совместимы с0.1. Подробности и PHP-пример — в [английском руководстве](../integration.md).
[Обновление upstream](../maintenance.md), [проверка провайдеров](../provider-review.md),
[API reference](../reference/api.md). Все формы проверены offline, реальные аккаунты — нет.

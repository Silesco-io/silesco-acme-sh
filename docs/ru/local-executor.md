# Локальный исполнитель для независимого Linux-приложения

Document ID: `acme-sh.local-executor`. Language: `ru`. Лицензия: CC BY 4.0.
Примеры кода сохраняют Apache-2.0. [English](../local-executor.md).

Это **необязательный синхронный исполнитель** для сторонних приложений. Сам
каталог и API запросов по умолчанию ничего не запускают. В Silesco Wizard/UI
должны использовать разрешённый bootstrap/Guard-путь, **не этого исполнителя**.
Новых веб-служб, фонового демона, Docker API, sudo или установщика библиотека
не добавляет.

## Что настраивает разработчик

Администратор предоставляет проверенный каталог исходников acme.sh, точно
совпадающий с `Catalog::upstream()` и `UPSTREAM.json`: версия 3.1.6, commit
`807da6498377ee5e0cf43a78091f46f12dc59a89`. Проверяются SHA-256 основного
скрипта и полный набор 198 DNS-драйверов. Нужны исходные Linux-байты LF;
замена переводов строк меняет контрольную сумму. GPL-3.0 runtime поставляется
отдельно: PHP-библиотека под Apache-2.0 не устанавливает и не обновляет его сама.

Исполнитель требует Linux, PHP 8.3+, расширения OpenSSL/POSIX, разрешённый
`proc_open`, `/bin/sh`, `/usr/bin/setsid`, `/usr/bin/timeout` и зависимости
acme.sh/явно выбранного DNS-драйвера. PATH ограничен `/usr/bin:/bin`, эти
программы нельзя подменять пользовательскими исполняемыми файлами. Отдельный
пользователь процесса должен иметь доступ к своему state и, для HTTP-01, к
выбранному каталогу challenge; root не требуется. Нужен сетевой доступ к CA,
DNS и выбранному провайдеру.

State-каталог заранее создаётся с правами 0700 и владельцем этого пользователя.
Исходники и файл доверенных CA — обычные проверенные файлы, без ссылок,
принадлежащие root либо пользователю процесса и без записи группе/остальным.
Пути не содержат пробелов или symlink; родительские каталоги защищены от
подмены, допустим root-owned sticky `/tmp` для тестов. Для реальной работы
нужно постоянное защищённое хранилище, а не исчезающий каталог `/tmp`.

Пример API приведён в [английском руководстве](../local-executor.md#trusted-setup).
В `Policy` разработчик явно задаёт исходники/state/webroot, HTTPS URL выбранного
CA, email, `acceptTerms` (согласие с условиями именно этого CA), файл доверенных
CA, максимальное время и список разрешённых DNS-драйверов. Эти параметры
не берутся из запроса браузера. В `CertificateRequest` нельзя передать shell,
команду, путь исполняемого файла, hook, CA или произвольный путь записи.

Тестовый CA bundle проверяет только полученный сертификат. Библиотека не
добавляет его в системные/провайдерские доверенные корни и не делает из этого
доказательство доверия браузера/PWA. HTTPS к API использует штатное доверие ОС.

## DNS и секреты

По умолчанию DNS запрещён. Разработчик явно разрешает, например,
`allowedProviders: ['dns_regru']`. Наличие всех драйверов в каталоге не означает,
что каждому безопасно дать права веб-приложения. Некоторые вызывают внешние
CLI, изменяют локальную DNS-зону или исполняют административную конфигурацию.
Перед разрешением читают закреплённый исходник и требования драйвера. Такие
командные/конфигурационные поля нельзя напрямую заполнять из недоверенной
веб-формы у привилегированного исполнителя. Список разрешений — решение
разработчика, не пользователя браузера.

`CredentialResolver::resolve($providerId, $reference)` извлекает утверждённые
реквизиты из хранилища приложения. Запрос содержит только непрозрачную ссылку.
Возвращаются точные имена полей upstream. `Catalog::validateCredentials()`
проверяет форму/вариант авторизации, но не работоспособность ключа через API
и не заменяет проверку безопасности драйвера. У API-ключа должны быть
минимальные права, насколько это позволяет провайдер.

Секреты передаются только в окружении дочернего процесса: не в аргументах,
журнале операции, результате или логах. Ошибка resolver заменяется стабильным
кодом, сырой вывод ограничивается и отбрасывается без разбора секретных ответов.
Дочерний процесс не наследует окружение PHP, debug/proxy/home/hooks/logs.
Debug, файловые логи и syslog выключены, accountconf новый для каждой операции.
Не запрашиваются notify/deploy/pre/post/reload hooks, cron, обновления или
`--insecure`.

Переменные окружения **не являются шифрованием**: Unix-пользователь процесса
и root могут их прочитать. acme.sh/драйверы могут сохранить API-реквизиты в
accountconf. Поэтому весь state — секретное хранилище: каталоги 0700, файлы
0600; нельзя выгружать его как диагностический архив. Шифрование кэша,
гарантированное уничтожение файлов и памяти PHP этим профилем не обещаются.
Разработчик отвечает за изоляцию процесса, хранение, сроки и защищённый backup;
реквизиты/resolver/окружение нельзя логировать или отладочно сериализовать.

## Выполнение и результат

`submit()` выполняется синхронно с единственной неблокирующей блокировкой
state. Его вызывают из доверенного обработчика задания, не из автоматически
повторяемого HTTP-запроса. Аргументы — массив argv, а не строка shell.
Закреплённый скрипт исполняет фиксированный `/bin/sh`; независимый GNU timeout
ограничивает работу даже после аварии PHP. Сырой stdout/stderr отбрасывается;
при превышении 1 MiB процесс останавливается. После TERM следует ограниченный
по времени KILL группы процесса.

Кода выхода 0 недостаточно: проверяются ограниченный PEM, точный набор DNS SAN
(в том числе wildcard), срок действия, соответствие закрытому ключу и цепочка
до заранее выбранного CA bundle. После fsync материала/журнала выдаётся `issued`.
В metadata — только публичные имена, fingerprint, serial и время, не PEM/ключ.
`issued` не означает переключение Nginx, готовность TLS маршрута или PWA.

Файлы находятся в
`<stateRoot>/local-<idempotencyKey>/certs/<первый-домен>_ecc/`:
`<домен>.cer`, `<домен>.key`, `ca.cer`, upstream `fullchain.cer`.
Уполномоченный код приложения сам безопасно читает, проверяет и активирует
их, затем проверяет настоящий TLS. Исполнитель не пишет в пути из браузера,
не перезапускает службы и не возвращает закрытый ключ в API прогресса.

## Повторы и отказы

Журнал содержит минимальные hash запроса/политики, deadline и безопасный итог,
не секреты и не stdout. Тот же idempotency key с тем же запросом/политикой
возвращает сохранённый результат без выпуска. Изменение —
`acme.request_conflict`. Ошибка/timeout также сохраняются: скрытых повторов CA
при `submit()` и `poll()` нет.

Перед первым возможным сетевым обращением записывается durable `running`.
Если PHP погиб, новый `submit()` не выпускает заново неизвестно завершившийся
сертификат: `acme.executor_unavailable`, после старого deadline —
`acme.request_expired`. `poll()` только читает, не продлевает срок и не запускает
работу. Незавершённый статус после deadline отображается как истёкший.
Администратор проверяет состояние CA/аккаунта/TXT/файлов и лишь затем явно
разрешает новый request ID. Удаление журнала или автоматический новый UUID —
не безопасное восстановление. После timeout может понадобиться ручная очистка
оставшихся TXT; библиотека не притворяется, что upstream успел её закончить.

В этой версии есть выпуск; автоматическое продление/отзыв/расписание,
восстановление неоднозначного результата, применение в службах и права Silesco —
отдельные контракты. Новый `--issue` с другим UUID нельзя выдавать за безопасное
бесшовное продление. Наличие 198 форм не является испытанием 198 аккаунтов.

`tests/local-executor.php` запускается в Linux с `ACME_SH_TEST_SOURCE`,
указывающим на закреплённый source. Он использует локальные фиктивные CA,
реквизиты и процессы: проверяет SAN/ключ/цепочку, ложный exit 0, ошибки/timeout,
отбрасывание секретного вывода, allowlist, повторы, рестарт, права/ссылки и
подмену исходников. Сеть не нужна. Перед настоящей интеграцией отдельным
разрешённым тестом проверяют LE **staging**, не частые перевыпуски production.

# Yii3 Wizard и общий контур настройки

Architecture baseline: 1.23.0. Принято владельцем: 2026-09-21.

## 1. Что меняется

Wizard становится временным приложением PHP/Yii3 в контейнере вместо Go web-бинарника. Nginx остаётся единственным публичным HTTP(S)-входом и используется как при установке, так и после перехода к основной панели. PHP runtime и переиспользуемые модули общие с панелью; bootstrap и configured являются разными режимами запуска с разными зависимостями и полномочиями. Это не разрешение запустить все UI workers до готовности системы.

`silesco-wizard` владеет сценарием первоначальной настройки и его тестами, `silesco-ui` — работающей панелью. Общая бизнес-логика выносится в независимые PHP-пакеты, а не копируется из одного приложения в другое. Первый такой пакет — `silesco-acme-sh`. Общий runtime не означает общие sessions, секреты или неограниченные mounts.

## 2. install.sh

1. Устанавливает собственные необходимые зависимости, включая jq, до первого использования; ошибки установки понятны и останавливают зависимые действия.
2. Спрашивает базовый домен. Не ограничивает его ровно двумя DNS-метками: registrable domain может иметь публичный суффикс вроде co.uk.
3. Проверяет адреса `install.<base-domain>` и непредсказуемого пробного имени для определения пригодности wildcard. Сам факт ответа на случайное имя не доказывает ownership или достижимость VPS. Сверяются адреса с доступным endpoint установки; сомнение или неподходящий DNS ведёт к IP-входу, а не к бесконечному ожиданию.
4. Если wildcard пригоден, сообщает адрес Wizard `https://install.<base-domain>`; иначе запускает по IP. Наличие только A/AAAA у apex не должно блокировать установку. Подсказки по изменению DNS находятся в Wizard.
5. НЕ выпускает сертификат LE и не требует DNS API credentials: первоначальный HTTPS использует self-signed сертификат и показывает fingerprint.
6. Поднимает Nginx и непривилегированный Yii3 bootstrap runtime, проверяет готовность, печатает кликабельную одноразовую ссылку входа и возвращает shell prompt. Не требует читать отдельный файл с токеном. Exact способ передачи токена и защита от попадания в access logs фиксируются в контракте до включения новой ссылки; журнал и runtime state не хранят plaintext token.

Существующие root journal, fixed apply/cleanup и detached lifecycle сохраняются. Отдельный постоянный root web-server, Docker socket в PHP и общая команда shell из UI не допускаются.

## 3. Bootstrap runtime

- Стартует без PostgreSQL, Vault, их credentials, migrations и готового администратора. Healthcheck bootstrap не вызывает UI `database:ready`.
- Использует ограниченные draft/session state и типизированные intent/result interfaces; authoritative root journal не становится writable для PHP.
- Работает non-root, с read-only rootfs, без Docker socket, privileged/host-network, лишних capabilities, host sudo или доступа ко всему `/run/silesco.io`.
- Nginx проксирует bootstrap к существующему exact Unix socket `/run/silesco.io/bootstrap/wizard/wizard.sock`. PHP runtime получает только необходимые leaf mounts и numeric identity/group. Socket route не требует нового публичного или host TCP-порта.
- Systemd управляет жизненным циклом контейнера через Installer; пользовательский PHP не управляет Docker.
- При `configured` root apply выключает bootstrap routes и его identity/session, переключает проверенную Nginx generation на UI. Общий PHP image/библиотеки не удаляются как прежний временный Go executable; временный bootstrap container/state очищаются. Ошибка переключения оставляет диагностируемый, восстанавливаемый этап, не фальшивый success.

Точный packaging/entrypoint выбирается при реализации на основе существующего Yii3 runtime. Обязателен реальный запуск без DB/Vault; простой запуск PHP development server не является production acceptance.

## 4. Общая ACME-библиотека

`silesco-acme-sh` (`silesco-io/acme-sh`) — framework-independent PHP-обвязка над upstream acme.sh. Каталог охватывает DNS providers закреплённой версии: поля, обязательность, варианты авторизации, secret markers, validation, ru/en labels/help и официальные ссылки получения credentials. Источники — upstream docs и соответствующий driver; не выдумывать API и не подменять полноту каталога утверждением, что каждый аккаунт испытан.

acme.sh сам создаёт и удаляет DNS-01 TXT через провайдера. `silesco-acme` сохраняет контейнер и runtime-обвязку. Общая библиотека формирует типизированные операции и принимает результаты через execution interface. Сторонний PHP-проект может подключить локального исполнителя без Silesco/Vault/PWA/PostgreSQL. В Silesco исполнитель отправляет операцию существующему bootstrap apply либо Guard/helper, не запускает произвольный shell из веб-процесса. Новый универсальный агент не создаётся.

Wizard и панель используют один каталог и одну логику ACME. Первый реальный DNS-01 сценарий — reg.ru; каталог этим провайдером не ограничивается. Формы показывают необходимые поля, подсказки и ссылки, затем реальный этап работы и понятный результат. Кнопка показывает loading из принятой UI-библиотеки и не создаёт параллельных запросов. Raw provider responses/credentials не становятся progress/logs.

## 5. HTTPS, PWA и совместимость

Wizard помогает выбрать адрес панели и HTTP-01 либо DNS-01. Wildcard DNS, wildcard certificate и способ ACME challenge — разные понятия. Адрес install временный; его TLS-покрытие при дальнейшем использовании планируется вместе с адресом панели, а не предполагается из wildcard DNS.

Смена языка/backend не отменяет session binding, одноразовость, CSRF, replay/TTL, root-проверку TLS и правила staging из ADR-088/089. PWA, KMS credentials и recovery admission не становятся доступными на self-signed IP только потому, что PHP заработал. Переход между origin требует отдельного проверенного сценария; ADR-090 остаётся действующим для старого профиля и не выкидывается без replacement contract. Не продолжать его реализацию как отдельную цель параллельно с миграцией.

Новый runtime — несовместимая упаковка Wizard, не patch старого ELF. Installer/Release обязаны различать поколения и проверять exact artifact. Новая установка и перенос активной старой session — разные задачи: первый этап ориентирован на чистую установку; молчаливое преобразование старого state запрещено. Публикация требует связного теста, не только новых snapshot.

## 6. Последовательность разработки и критерии завершения

Работа идёт последовательно; следующий этап не заменяет закрытие текущего.

1. **Архитектура:** ADR, baseline, generator, snapshots затронутых проектов согласованы. Старый Go runtime не называется целевым. Это документационная готовность, не работающий Wizard.
2. **Запуск:** Yii3 bootstrap entrypoint без DB/Vault; Nginx→Unix socket; install.sh domain/DNS/dependencies и вывод адреса. Тест: чистая Ubuntu 26.04, один запуск Installer, страница действительно открывается; закрытие SSH не гасит её. До прохождения этого теста не начинать KMS/PWA перенос.
3. **ACME:** общий PHP каталог/исполнитель, формы HTTP-01/DNS-01, progress и повтор ошибок. Тест: LE staging, ошибки DNS/credentials, успешная активация согласованного install/panel TLS и продолжение той же установки. Mock success не заменяет реальную выдачу.
4. **Завершение настройки:** последовательно перенести существующие KMS, Vault, PWA, recovery и Master commit, сохраняя владельцев секретов. Проверить каждый связный сценарий до следующего. Не переписывать криптографию ради смены языка Wizard.
5. **Релиз-кандидат:** чистая VM устанавливается только через собранный install.sh/package, без ручного добавления файлов; bootstrap удалён, Master/PWA доступны, reboot пройден. Затем preview и отдельно разрешённая публикация get.silesco.io.

Результат каждого этапа — commit, команды/результаты тестов, незакрытые ограничения. Ни один промежуточный этап не объявляется готовой альфой. Текущий предел расхода Codex — 50%, без использования reset credits.
